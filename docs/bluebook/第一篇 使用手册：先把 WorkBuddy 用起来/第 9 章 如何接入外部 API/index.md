# 第 9 章 如何接入外部 API

> 内容来源：WorkBuddy 官方文档 · 连接器 / MCP（非官方整理，© 本指南作者，保留所有权利）

第 7 章你已经会装现成的连接器——QQ 邮箱、腾讯文档，点几下就能用。但现实里总有一些"装不到"的服务：公司内部的知识库、自己写的小工具、某个小众平台。

这一章教你把**任何**服务接进 WorkBuddy。听起来像程序员的事，其实你只需要会**抄一段配置、存到指定位置、点一下信任**，三步完事。

## 一、先想明白：为什么要"接"

打个比方：WorkBuddy 会说"AI 语言"，第三方服务只认"API 语言"（一套固定的请求规则）。

两者对不上话，就需要一个**转接头**。

- 装现成连接器 = 买一个出厂配好的转接头；
- 自定义连接器 = 按说明书画一个自己的转接头。

这个"转接头"的技术名字叫 **MCP**（Model Context Protocol，模型上下文协议）——你不用记全称，只要知道：**它是 AI 和外部工具之间的通用插头标准**。服务只要按这个标准做插头，WorkBuddy 就能插上就用。

## 二、接入方式：两条路，小白走第一条

官方给两种方案：

| 方案 | 适用场景 | 小白建议 |
|---|---|---|
| **MCP + Skill**（推荐） | 有 API 服务，或能找到现成 MCP Server | 就走这条 |
| CLI + Skill | 已有成熟的命令行工具 | 先不管，需要时再看 |

一句话：**服务能通过网络访问就用 MCP**；CLI 方案等哪天你真的用上了再说。

MCP 服务又分两种形态：

- **远程**：服务跑在某个网址上（大多数第三方 API 是这种）；
- **本地**：服务跑在你自己电脑上的一个程序里（公司内网工具常见）。

## 三、动手：写一段 mcp.json

WorkBuddy 的自定义连接器配置集中在一个文件里：

**用户级配置文件**（对所有项目生效）：`~/.workbuddy/mcp.json`
（Windows 下就是 `C:\Users\你的用户名\.workbuddy\mcp.json`）

**形态一：本地程序（stdio 模式）**

```json
{
  "mcpServers": {
    "enterprise-knowledge": {
      "command": "python",
      "args": ["C:/path/to/knowledge_server.py"],
      "env": { "API_TOKEN": "your-api-token-here" },
      "description": "企业内部知识库查询系统"
    }
  }
}
```

读法：让 WorkBuddy 启动 `knowledge_server.py` 这个程序当转接头，凭据放在 `env` 环境变量里。

**形态二：远程服务（HTTP 模式）**

```json
{
  "mcpServers": {
    "remote-service": {
      "url": "https://api.example.com/mcp/",
      "headers": { "x-api-key": "sk-xxxxx" }
    }
  }
}
```

读法：直接指向一个网址，key 放在请求头里。大多数第三方 MCP 服务给的就是这两行。

**没有 OAuth、只有长期 Token 怎么办？** 官方支持「用户自填 Token 模式」：像上面两个例子那样，把对方发给你的 API Key 填进 `env` 或 `headers` 即可，不必走授权跳转。

**新手必踩的坑：密钥泄露。**

- 配置里的 token 一律用**占位符或环境变量**，别把真实密钥硬编码后提交到代码仓库；
- 官方建议敏感信息走环境变量（如 `${API_TOKEN}`），配置文件本身可以放心备份；
- 抄网上配置前，先看一眼它要什么权限——最小权限原则。

## 四、信任与启用

配置写好、文件保存后，回到 WorkBuddy：

1. 打开**连接器管理**；
2. 找到新添加的连接器；
3. 点**「信任」**——这是安全机制：新装的服务必须你亲自点头才生效；
4. 打开开关**启用**。

这一步和第 7 章装现成连接器完全一样，只是来源从"官方市场"换成了"你自己的配置"。

## 五、验证：说一句话试试

在对话框直接说：

> 帮我查一下企业知识库里关于「XX 项目」的文档

如果 WorkBuddy 调用了你配置的服务并返回结果，接入成功。没反应的话，按顺序查三处：JSON 有没有多逗少逗、路径对不对、信任开关开了没有。

## 本章任务清单

- [ ] 想清楚要接什么服务（公司内部工具 / 第三方 API / 自己的小工具）
- [ ] 打开（或新建）`~/.workbuddy/mcp.json`，抄入一段最小配置
- [ ] 在连接器管理里完成「信任 → 启用」
- [ ] 用一句自然语言验证调用成功
- [ ] 检查配置里没有明文真实密钥

## 小白说明书

> **API**：程序之间互相调用数据的固定接口，像餐厅的点菜窗口——按规矩下单就能拿到菜。
>
> **MCP**：Model Context Protocol 的缩写，AI 和外部工具之间的"通用插头标准"。
>
> **MCP Server**：提供能力的那一端服务，可以是远程网址，也可以是你电脑上的一个程序。
>
> **stdio / HTTP**：两种连接形态。stdio = 启动本地程序来通信；HTTP = 访问一个网址。
>
> **Token / API Key**：访问服务的钥匙，一串字符。泄露了别人就能冒充你，所以要放进环境变量。
>
> **环境变量**：操作系统层面的"隐藏小本子"，程序运行时才去读，避免把密钥写死在文件里。
