# 第 22 章 打造 Skill：将书和视频蒸馏为可执行 Skill

> 内容来源：WorkBuddy 官方指南与社区实战案例整理（非官方，© 本指南作者，保留所有权利）

<Paywall part="3" variant="banner" />

你一定有过这种体验：收藏夹里躺着 100 篇干货，B 站收藏了 20 个教程视频，
真要干活的时候一条也想不起来用。**收藏 ≠ 能力，看懂 ≠ 可执行**。

WorkBuddy 的 Skill 机制给了这个问题一个漂亮的答案：把一本书、一套课程、
甚至你自己踩坑三年的经验，**蒸馏成一个"说到就触发、触发就按你的规矩办"的
专属技能**。这一章教你完整走一遍这条蒸馏流水线——它也是本篇最重要的一章。

![一只小黑坐在书前，把书里的精华蒸馏进一个小瓶子](./images/22-hei-skill.png)

*配图为示意插画，用于帮助理解本章主题，与实际软件界面无关。*

## 一、先想清楚：这个 Skill 值不值得做

动手前先用五问定标。做 Skill 和做任务不同，多问自己两个"复用性"问题：

| 问题 | 要说清什么 | 反例（不值得做） | 正例（值得做） |
|-|-|-|-|
| 目标 | 这个 Skill 替你做哪类活 | "帮我写东西"（太泛） | "按我的栏目结构拆解热点、产出公众号初稿" |
| 受众/口径 | 输出给谁看、什么语气 | 无固定口径 | 每周固定发公众号，要求口语化、有案例 |
| 材料 | 方法论从哪来 | 凭模型自带的通用知识 | 一本你认可的书 + 你 10 篇历史爆文的写法 |
| 触发 | 什么话应该唤起它 | 想不起来说什么 | "拆解这个热点""按我的风格写初稿" |
| 验收 | 怎么判断 Skill 做成了 | "感觉还行" | 新开对话说一句触发词，3 次里 3 次按你的结构输出 |

**判断标准一句话：如果这个活你以后每周都会干、且每次要求基本一致——就值得
做成 Skill；只干一次的活，直接写提示词就行，别过度工程。**

## 二、先选对 Skill：造技能需要的工具组合

| Skill 名称 | 适合处理 | 本章怎么用 | 注意点 |
|-|-|-|-|
| **skill-creator** | 创建/修改技能 | 主力工具：把方法论生成为标准 SKILL.md 结构 | 零代码，对话里就能完成 |
| **find-skills** | 找技能 | 先看看别人有没有做过类似的，避免重复造轮子 | 也能帮你检查自己写的技能描述 |
| **写书类技能（如福帮手写书）** | 长内容生产 | 蒸馏"写书类"方法论时参考其章节组织方式 | 属社区技能，按需安装 |
| **内容工作台类技能** | 内容生产流水线 | 参考成熟内容类 Skill 的结构（知识库/规则/模板分离） | 适合作为"抄结构"的对象 |
| **pdf / Markdown Converter** | 材料解析 | 把书的 PDF/讲稿转成可分析的文本 | 转换 ≠ 蒸馏，转换只是第一步 |
| **视频字幕类工具/技能** | 视频课转文字 | 把教程视频的字幕或逐字稿抽出来当原料 | 有字幕用字幕，没字幕先转文字 |

> **零成本提示**：本节所有技能均免费。先用 find-skills 搜"书名关键词 + 笔记/写作"，
> 十有八九有人做过近似技能——参考它的结构，再写你自己的，比从零开始快一倍。
