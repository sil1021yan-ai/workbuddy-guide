一、AI 是怎么工作的（先看这组） ​

术语人话解释
AI Agent（智能体）能自己拆步骤、调工具、动手干活的 AI。"代理"就是替你做事——你交任务，它自己执行给你结果。
提示词（Prompt）你给 AI 的那段话。说得越具体越不容易猜错。但 WorkBuddy 的思路是你讲清目标就行，不用自己拆步骤。
工具调用（Tool Call）AI 自己"伸手"操作外部东西：打开 Excel、读网页、跑脚本。这个过程你能看到。
结果区 / 产物产物 = 它做完交付给你的东西（文档、表格、PPT、报告、图片）。结果区 = 放这些东西的地方。
上下文（Context）你递给它的背景资料。同一个需求，给不给上下文，质量差很多。
@ 引用输入 @ 弹出可选项，选中的文件就"贴"进需求里，等于说"参考这个"，不用翻路径。
待确认它停下来等你回答。你不回话它就一直停着——这是最需要你介入的状态。
归档 vs 删除归档 = 收起来，以后还能找到。删除 = 永久消失，恢复不了。不确定就归档。

完整版收录 96 个术语，这里只放了 29 个最常用的。

二、Skill（技能） ​

术语人话解释
Skill（技能）打包好的操作手册 + 执行脚本。类比：提示词是你每次口头交代一遍，Skill 是写成了 SOP 贴在墙上。
启用 / 关闭 / 卸载启用 = 让它干活；关闭 = 暂停，随时能开回来；卸载 = 彻底删掉，找不回来。只想让它暂时别用，用关闭。
上传 / 查找 / 创建装 Skill 的三条路：上传 = 你已有包；查找 = 你说需求它帮你找；创建 = 现成的都不行它帮你写。新手用得最多的是查找，因为不用记名字。
本地技能包一个 .zip 文件装着 Skill 全部内容。别人做好了发给你，用「上传技能」导入。
误调用你启用了 10 个 Skill，它在你只想改错别字时顺手给你群发邮件。启用的越杂越容易发生。

三、专家与专家团 ​

术语人话解释
专家（Agent 型）给 AI 换一个人设和专业身份。召唤"文档评审官"，它就用评审官视角看稿。
人设 + 方法论 + 工具链专家的三个组成：我是谁（人设）／我怎么做事（方法论）／我能干什么（工具链）。
专家团多位专家 + SOP 编排。谁先做、谁后做、怎么配合。
积分消耗倍数专家团要调多个专家多轮交互，消耗是单专家的 3–5 倍。
专家名不可改创建后名字改不了，想换只能重建。所以别叫"专家1"。

四、连接器与 API ​

术语人话解释
连接器（Connector）把外部服务接到 WorkBuddy 上的一道门。类比：Skill 是教它做事，连接器是给它门钥匙。
授权 / 扫码授权让第三方服务同意"WorkBuddy 可以代表我访问我的数据"。扫一次码就等于把钥匙交出去了。
MCPModel Context Protocol，AI 和外部工具之间的"通用插头标准"。
环境变量操作系统层面的"隐藏小本子"，程序运行时才读，避免把密钥写死在文件里。
解绑 vs 停止使用停止使用 = 临时关闭，授权还留着；解绑 = 撤销授权，下次要重新授权。
权限边界三条独立授权（连一个≠连全部）／不主动抓取（不下指令就不取）／不超出已有权限（你读不到的它也读不到）。

五、自动化与可靠性 ​

术语人话解释
自动化 / 触发到点自动跑。配置一次，按规则反复执行。
权限模式限制无人值守任务能"动"多少东西的开关。默认更安全。
工作空间任务执行时所在的文件夹。自动化默认分配 automation-xxxx 目录。
推送任务完成后把结果发到小程序或企业微信，不用守在电脑前。
无人值守没人盯着自动运行。所以涉及删文件、花钱的提示词要格外谨慎。
